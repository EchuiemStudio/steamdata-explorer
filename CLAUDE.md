# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SteamData Explorer — a static, no-build multi-page site that browses a sampled
snapshot of ~700 public Steam games (genres, tags, price, review data). Plain
HTML/CSS/vanilla JS, no framework, no bundler, no server. Chart.js, GSAP,
ScrollTrigger, and Lenis are loaded from CDN `<script>` tags, not npm.

The project is mid-pivot toward becoming a broader multi-section info hub
(Supabase-backed, automated data pulls), with the Steam dataset becoming one
section among others. That work hasn't landed in this repo yet — nothing
Supabase-related exists here as of this writing — but expect new sections to
show up alongside the existing Steam pages rather than replacing them.

## Commands

There is no build, lint, or test script — `package.json` only declares
`playwright` as a devDependency (no config or spec files exist yet; it isn't
wired up to anything).

- **Serve locally**: the pages `fetch()` `data/*.json`, which fails under
  `file://`. Serve the repo root with any static server, e.g. `npx serve` or
  `python -m http.server`.
- **Pull fresh Steam data** (slow — multi-minute, rate-limited to be polite to
  Steam's undocumented endpoints): `node scripts/fetch-steam-data.js`. Rebuilds
  `data/games.json` and `data/aggregates.json` from scratch via a stratified
  hit/mid/niche sample (see constants at the top of the file to adjust sample
  size, review floor, etc).
- **Refresh news only**: `node scripts/fetch-news.js` — pulls RSS feeds into
  `data/news.json`. Also runs daily via `.github/workflows/refresh-news.yml`
  (auto-commits if the file changed).
- **One-off data migrations** live as standalone scripts, e.g.
  `scripts/backfill-release-month.js` — these mutate `data/games.json` in
  place and are run by hand once, not part of any regular pipeline.

## Architecture

**Pages** (each a standalone HTML file, no router): `index.html` (home),
`browse.html`, `opportunity.html`, `Test_OpportunityMap.html` (experimental
axis-picker variant of the Opportunity Map, `data-page="test-opportunity"`),
`news.html`. Each `<body>` carries `data-page="..."` (used by nav to highlight
the active link) and `data-base` when deployed under a subpath (read by
`sitePathPrefix()` in `scripts/nav.js` and `scripts/data.js` to prefix fetches
to `data/*.json` and `partials/nav.html`).

**Shared nav**: `partials/nav.html` is fetched and injected into
`#nav-placeholder` at runtime by `scripts/nav.js` — it is not duplicated per
page.

**Data layer**: `data/games.json` (per-game records) and
`data/aggregates.json` (precomputed cross-game stats: genre counts, tier
stats, tag co-occurrence) are static JSON files, not an API. They're
regenerated by the Node scripts above, committed to the repo, and read
client-side via plain `fetch()`. `performance_tier` (`hit`/`mid`/`niche`) is
assigned once at fetch time by percentile-ranking review counts across the
whole sampled pool — it's a fixed label on each game record, not recomputed
client-side.

**Script composition per page**: pages load a shared set of scripts (in
dependency order via `<script defer>`) and then a page-specific
`init<Page>Page()` entry point that wires them together:
- `scripts/data.js` — data loading (`loadGames`/`loadAggregates`), formatting
  helpers, review-keyword text extraction, and the `VIZ_*` color constants
  (must be kept in sync by hand with the `--viz-*` custom properties in
  `styles/tokens.css` — Chart.js can't read CSS variables).
- `scripts/filters.js` — `createFilterPanel()`, the shared searchable
  genre/tag picker used on the home/browse/opportunity pages; genres and tags
  are treated as one unified label facet (they overlap ~86%), not two
  separate filter groups.
- `scripts/cards.js` — game card HTML + `renderGameGrid()`, which diffs
  against existing DOM nodes by `data-appid` rather than clearing and
  rebuilding the whole grid on every filter change.
- `scripts/scatter.js` / `scripts/chart-interactions.js` / `scripts/insights.js`
  — Chart.js chart builders (scatter plots, extremes bar charts, tag
  frequency / review keyword diverging bars). Axis bounds are deliberately
  computed from the *full* dataset, not the currently filtered subset, so
  filtering moves points without rescaling the axes.
- `scripts/motion.js` — GSAP/ScrollTrigger reveal animations + Lenis smooth
  scroll; opts individual elements in via `data-reveal` and out of Lenis
  capture via `data-lenis-prevent`.
- `scripts/home.js`, `scripts/browse.js`, `scripts/opportunity.js`,
  `scripts/test-opportunity.js`, `scripts/news.js` — one per page, each calls
  its own `init<Page>Page()` at the bottom of the file.

**Styling**: `styles/tokens.css` holds all design tokens (the "Brass &
Graphite" dark theme — warm charcoal surfaces, brass/copper accents, fixed
hue-per-tier for hit/mid/niche) as CSS custom properties; `styles/main.css`
(~1100 lines) holds every component style, no preprocessor or CSS modules.
